## T2 cache lifetime (`experiments/session-probe.mjs`, plan `experiments/plans/cache-lifetime.json`)

Design: one session per gap; turn 1 reads 400 unique lines of `src/delivery-service.mjs` behind a random nonce, turn 2 is "repeat your answer, no tools" after the gap. Per-turn figures are differences of the CLI's cumulative usage files.

- The CLI's own `cacheExpiresAt` is always turn end + 30 min, both models.
- Luna: shared ~5.3k-token system prefix hit at 1, 10, 25 min; missed at 35 and 45 min. Consistent with a 30 min TTL.
- Sol: hit at 25 min, **missed at 10 min and 35 min**. One run per cell; the 10-min miss says hits are best-effort, not a fixed TTL. Do not plan on Sol cache hits.
- **Bigger finding:** in every session, at every gap including 1 min, the session's own turn-1 content (about 4.3k tokens) was cache-written again on turn 2. Only the system prefix ever hit. Same pattern in T4 (`stay-sol` turn 2: read 5345, write 2285) and in the earlier smoke run at a 5 s gap.
- **[INFERRED]** A `copilot -p --session-id` resume rebuilds the history in a form that does not match the prefix the previous process cached (or the cache key differs per process). Every benchmark turn in HANDOFF/HANDOFF-2 that used `-p` resumes paid cache-write on the whole history each turn. Interactive sessions were not measured for this. Check before trusting multi-turn `-p` numbers as "what an interactive user pays".
- A first attempt of this probe was aborted (12.56 credits, folder `handoff/raw/probe-cache-lifetime-aborted-shared-prefix/`): every session had read the same lines with no nonce, so the sessions warmed each other's prefix and the gaps measured nothing.
- Cross-session prefix sharing was observed directly: `switch-to-luna` turn 1 (Sol) read 11,776 cached tokens and wrote 0, straight after `stay-sol` had sent the same prompt from a different directory. The working directory is not part of the cached prefix.

### Stall and runner bug found here

- Sol medium run 3: the CLI session stopped making model calls after ~08:53Z and only logged `session.managed_settings_resolved` once an hour. No usage file, so 0 credits recorded; the true spend is unknown.
- The benchmark's timeout sent SIGKILL to the `copilot` launcher only. The real binary survived as an orphan holding the stdout pipe, so `close` never fired and the run hung for 3 h 17 min until killed by hand.
- Fixed in `shunt-copilot/scripts/benchmark.mjs`, `experiments/ladder.mjs`, `experiments/session-probe.mjs`: spawn `detached: true`, kill the process group on timeout, destroy the pipe. Unit tests 38/38 and 12/12.
- Every earlier run in the ledger used the old code; none of them hung, so their figures are unaffected.
